# 한 칸 상회 · ハンカン商店

한국어/일본어와 USD를 지원하는 독립 실행 HTML 자판기 회사 경영 게임입니다. 외부 API나 서버 없이 실행하며 저장은 현재 브라우저에 남습니다.

사계절이 변하는 타일형 도시와 실시간 영업 장면을 보면서 Windows 95 스타일의 업무 창으로 발주·생산·직원·연구·재무를 관리합니다. 업무 창은 최소화하거나 닫고 회사 메뉴에서 다시 열 수 있습니다. 작은 화면에서도 도시를 위쪽에 유지합니다.

## 실행과 개발

Python 3.10 이상, Node.js 24, Git이 필요합니다.

```sh
git clone https://github.com/eunyoeongmin/hankan-vending-tycoon.git
cd hankan-vending-tycoon
npm ci
python build.py
npm test
npm run test:balance
python -m http.server 8765 --directory dist
```

http://localhost:8765 또는 `dist/index.html`을 열어 실행합니다. 다른 컴퓨터에서는 저장소를 받아 개발할 수 있습니다. 게임 저장은 브라우저/주소별로 분리되며 GitHub에 업로드되지 않습니다.

`src/`가 원본이며 `build.py`가 `dist/index.html`과 상위 폴더의 `vending-tycoon.html`, 개발 메모 사본을 생성합니다. `dist`를 직접 수정하지 마세요. `.openai/hosting.json`은 공개 사이트의 연결 정보입니다. 인증 정보는 저장소에 포함하지 않습니다.

## 10.3.1 시스템 점검

타사 음료는 상품 연구 없이 매입·판매하고, 자체 상품 개발은 연구를 요구합니다. 기기의 저온·온장 설비와 슬롯 재고는 진열 조건으로 확인합니다. 자동 운영은 상환 원금을 유보하고 최소 발주 계약을 지키며, 정지하면 정기 배송도 멈춥니다. 신규 중고·리스 견적은 현행 기기 가격과 연동합니다. [전체 점검·수정 내역과 밸런스 비교](docs/SYSTEM_AUDIT_10.3.1.md).

## 10.3 사업 사건

40종 사건을 실제 영업과 연결했습니다. 후원·할인·발주·고장·직원 이직·계약 갱신·연구 실패 등을 비용과 기간을 비교해 결정하고, 보류하면 영업을 계속할 수 있습니다. 결과 장부에서 실제 지출과 판매 기록, 경쟁사 참여, 지연 작업 결과를 확인합니다. [40종 조건과 선택 대조표](docs/EVENT_AUDIT.md).

변동금리 차입을 선택할 수 있으며 기존 고정 계약은 유지합니다. 사건은 사업 상태에 맞춰 발생하므로 공장·직원·대출이 없는 회사에는 해당 사건이 나오지 않습니다. 인간 플레이를 통한 세부 밸런싱은 계속 필요합니다.

## 10.0 장기 경영

- 기본 자유 경영, 2000-01-01 시작과 달력 계절. 1배속 하루 3분, 0.5/2/4/16/64/256배속. 메뉴·다른 브라우저 탭·필수 사건은 정지하며 하나의 시계로 결산합니다.
- 판매 상품만 수요·창고·기기·배송 대기량을 보고 발주합니다. 일 예산과 현금 유보, 7일 내 지급 예정액을 지킵니다. 가격은 직접 유지/마진/판매 확대를 선택합니다.
- 첫 거점은 사장이 관리하며 최대 2대 경로를 배송합니다. 확장 거점은 관리자, 배송은 직원·차량·경로가 필요합니다. 화물은 실제 재고이며 차량은 여러 기기에 적재량을 나눠 배송합니다.
- 협력사 투자와 기간형 연구 후 자체 공장을 건설합니다. 신규 연구의 기본 작업량은 기술 단계당 90일이며 협력사 연구 인원·동시 프로젝트·사내 연구소로 달라집니다. 선납 예산 내 단계 승인과 추가 투자 결정을 구분합니다.
- 계속 생산은 공장별 상품·목표 재고·회당 생산량을 설정합니다. 원재료 발주→입고→생산 직원/관리자→공정→완제품→배송→판매로 연결됩니다. 추가 거점의 팀과 관리자, 교육/피로/급여는 실제 처리 능력에 반영됩니다.
- 급여는 월말, 세금은 월 손익에 따라 발생합니다. 월 장부는 최대 10년을 보관합니다. 일 장부와 월 장부의 손익/현금흐름을 구분합니다.
- 은행은 하나의 계약 장부를 사용합니다. 신용·순자산·영업 현금흐름으로 한도를 계산하고 연 이율로 계약합니다. 운전자금 3개월 일시상환, 설비 24개월/원금 3개월 거치, 회사채 36개월/6개월 흑자 요건입니다. 일별 이자 발생과 월 지급, 원금과 비용, 부분상환과 연체를 구분합니다.
- 경쟁사도 같은 조달·배송·고용·생산·자금 제약을 사용합니다. 월 손익과 현금에 따라 가격·연구·증설·물류 투자·합병을 결정합니다. 회사별 승패와 성장 경로는 보장하지 않습니다.
- 초기 정상 자금과 새 기기·공장·연구 투자 비용을 분리했습니다. 자동화로 인한 즉시 증설을 줄이기 위한 초기 보정이며 본격적인 수치 밸런싱은 별도입니다.

기반 규칙의 배치별 FEFO, 제조사 SKU와 용량, 시설 계약, 브랜드, OEM/도매, 유한 공급사, 증권·기업집단·실물 인수, 다회사 공통 고객 시장은 유지합니다. 전체 산업이나 원작 게임의 모든 규칙을 복제한 것은 아닙니다.

## 화면과 저장

상단 상태바·좌측 회사 메뉴·중앙 작업 화면·하단 기록의 고정형 UI입니다. 한 화면에서 업무를 전환하며 긴 표는 내부에서 스크롤합니다. 시작 화면에는 닫기 버튼이 없고 게임 중 메뉴는 닫아 돌아올 수 있습니다.

브라우저 언어와 저장된 선택을 참고하며 `?lang=ja` / `?lang=ko`를 지원합니다. 시작과 게임 상단에서 언어를 직접 바꿀 수 있습니다.

새 게임은 10.0 규칙입니다. 기존 저장은 자동 전환하지 않습니다. 9.0 저장에서는 **장기 경영 전환**, 이전 저장에서는 먼저 **사업 규칙 전환**을 선택합니다. 전환 전 원본을 별도로 보관하고 기존 차입 금리/만기·연구·배송·외상 조건을 유지합니다. 전환 저장의 자동 운영은 **운영 규정**에서 직접 켭니다.

## 구조와 검사

- `base`, `enterprise`, `industry`, `market` 등: 단일 시계와 기존 저장/시장/회계.
- `supply-chain`, `organization`, `reference-*`: 조달·배치·공장·인력·연구·시설·기업집단.
- `management-core/finance/operations/ui`: 장기 경영의 달력·결산·차입·운영 정책·화면. 기존 규칙과의 경계를 명시합니다.
- `npm test`: 기존 시스템·사건·전체 점검 22묶음 회귀.
- `npm run test:balance`: 이전 규칙의 장기 표본과 신규 3난수 × 최대 731일. 기본 자금과 추가 자금의 후반 검사, 자동 검사와 인간 난도 평가를 구분합니다.
- `npm run test:browser`: 9묶음. Playwright/Edge가 필요하며 기본 주소는 `http://127.0.0.1:8765/`, `GAME_URL`과 `BROWSER_EXECUTABLE`로 변경합니다. Playwright는 별도 도구 디렉터리에 설치하고 `NODE_PATH`로 연결할 수 있습니다.

GitHub Actions는 빌드·회귀·장기 검사를 실행합니다. 실제 브라우저 확인과 공개 배포 근거는 개발 메모에 따로 기록합니다. `?debug=1`의 시험 조작은 일반 플레이 화면과 구분됩니다.

인간 플레이와 전략 간 수익률·투자 회수·경쟁 강도의 본격 보정은 아직 완료하지 않았습니다. 자동 검사 통과를 재미나 난도 검증으로 취급하지 않습니다.
