한국어/일본어와 USD를 지원하는 독립 실행 HTML 자판기 회사 경영 게임입니다. 외부 API나 서버 없이 실행하며 저장은 현재 브라우저에 남습니다.

- 공개 게임: https://hankan-vending-tycoon.eym7443.chatgpt.site
- 공개 소스: https://github.com/eunyoeongmin/hankan-vending-tycoon
- 개발 방향·구현 이력·검증 한계: [DEVELOPMENT.md](DEVELOPMENT.md)
- 현재 완료 체크·부분 완료·미착수·다음 작업은 위 상태표를 기준으로 확인합니다. [과거 기록과 사용자 기획 원문](docs/DEVELOPMENT_HISTORY_2026-09-10.md)은 별도 보관합니다.

## 실행과 개발

Python 3.10 이상, Node.js 24, Git이 필요합니다.

```sh
git clone https://github.com/eunyoeongmin/hankan-vending-tycoon.git
cd hankan-vending-tycoon
npm ci
python build.py
npm test
npm run test:balance
python -m http.server 8080 --directory dist
```

http://localhost:8080 을 열거나 `dist/index.html`을 직접 열어 플레이합니다. 저장은 브라우저와 접속 주소별로 분리됩니다. GitHub에는 사용자의 저장 데이터가 올라가지 않습니다.

`src/`가 수정 원본이며 `build.py`가 엔진과 UI를 합쳐 `dist/index.html`을 만듭니다. 상위 작업 폴더에는 `vending-tycoon.html`과 개발 메모 사본도 생성합니다. `dist`를 직접 수정하지 마세요.

- `base.html`: 기존 게임·지도·장면·단일 시계
- `enterprise.js`, `market.js`: 상품·슬롯·재고·회계·고객 시장
- `rivalry.js`, `scenario.js`, `trade.js`: 전략·시작 조건·기기 협상
- `industry.js`: 회사별 자원·공통 조달/금융/계약·다회사 고객·기업 인수·진입/퇴출
- `workspace.js`, `office.js`, `industry-ui.js`: 고정 경영 화면과 회사 메뉴
- `expansion.js`, `expansion-ui.js`: 제조·증권·합병·신도시·폐기·지연 사건·담보·자동화와 추가 작업 화면
- `supply-chain.js`, `organization.js`, `supply-chain-ui.js`: 외부 음료/기기 회사, 기간형 연구 계약, 직무별 고용/교육/처리량, 자재·공장 운영 및 조달 업무 화면

GitHub Actions는 빌드와 회귀·장기 시뮬레이션 검사를 실행합니다. `.openai/hosting.json`은 기존 공개 사이트 연결 정보이며 로컬 실행에는 인증이 필요하지 않습니다. 배포 인증 정보는 저장소에 포함하지 않습니다.

## 9.0 검토 버전

사업장·차량·배치 재고·제조사 SKU·공급 계약·단계형 연구·공정 생산·인력 시장·시설 계약·기업집단을 연결했습니다. [70개 구현 대조표](docs/REFERENCE_IMPLEMENTATION.md)와 [검사/공개 상태](DEVELOPMENT.md)를 확인하세요. 검토 브랜치와 현재 공개 게임의 버전은 다를 수 있습니다.

새 게임은 새 규칙을 사용합니다. 기존 저장은 **사업 운영 → 규칙 적용**을 눌러 전환하며 원본을 별도로 보관합니다. 연구 검토와 급여/외상 만기, 자회사 운영자금은 직접 관리해야 합니다.

`reference-core/operations/commerce/production/equipment/finance/market/decisions/hooks/completion/group/reporting/ui/ui-extra.js`는 새 규칙의 상태·업무·거래·연결·화면을 담당합니다. 기존 7/8 규칙의 회귀 검사는 유지됩니다.

## 경영 시스템

- 초기 4상권·24입지, 항만 신도시 개방 후 5상권·30입지. 새 게임에서 경쟁 회사 1/2/3곳과 회사당 초기 기기·현금, 사건 빈도, 공급 위험, 경기·물가·공격성·운영 능력 등을 선택합니다. 입문·표준·도전·극한 프리셋, 기간 평가 또는 자유 경영을 제공합니다.
- 기기별 4슬롯, 상품·가격·브랜드·용량·상태. 상품 변경 시 기존 재고는 창고로 돌아갑니다.
- 공통 시장의 각 고객이 플레이어 또는 경쟁사 중 한 곳에서 구매하거나 구매를 포기합니다. 실제 재고 차감·매출·원가가 회계와 구매 장면의 기준입니다.
- 모노벤드·아틀라스 유통·노바 드링크가 독립 현금·재고·주문·배송·작업·임금·연구·브랜드·부채를 운영합니다. 회사마다 상품·가격/광고·투자 정책이 다릅니다. 같은 상권의 NPC끼리도 경쟁합니다.
- 음료 공급 3사와 기기 제조 2사의 유한 재고·대금·품질. 기기 주문→배송→설치 대기→별도 계약 입지 설치. 음료 배송은 Aqua/Sun 기본 1일, Value 3일에 입출고 처리 시간이 더해집니다. 재고는 평균 원가로 회계 처리합니다.
- 7직무 직원의 개별 급여·숙련·지역 배치·교육. 교육 중 업무 제외/급여 지급, 정비·입고 대기열과 생산 처리량에 인력 반영. 새 규칙에서는 창고 재고만 보충합니다.
- 협력사 프로젝트에 개발비 투자, 인력·기간에 따라 예산 집행 후 상품/공정 기술과 이후 구매·제조 기기의 효율 개선. 60일 독점에는 투자금 50% 추가와 경쟁사 동일 협력사 기술 연구 제한이 있습니다. 주식 거래와 별개입니다.
- 공급 계약: $15 계약금, 30일 단가 고정과 공급처 제한, 중도 해지 $5. 입지 계약: 기본 임대료 3일분 계약금, 30일 임대료 15% 할인·고정. 회사마다 동일한 계약 함수를 사용합니다.
- 맞불 할인·단골 확보·방어 광고, 경쟁사 공세 예고와 투자/철수 로그. $20 시장조사는 조사 당시 재무 상태 등급·매출 추세를 제공합니다.
- 기기 인수와 매각은 금액 제안·거절/재제시·계약을 거칩니다. 기업 전체 인수에서는 실제 자산·기술·현금·부채를 승계합니다. 일반 경쟁 화면에는 상대의 정확한 재무를 표시하지 않으며, 인수 계약 검토에서 승계 금액을 확인합니다.
- 은행: 자산/신용 기반 대출, 최대 원금 $1,000, 신용에 따른 일 이율, 60일 만기·조건부 연장. 자금난이 7일 이상이고 회복 여력이 없을 때 파산합니다. NPC도 대출과 자산 처분을 먼저 검토합니다.
- 경쟁사 철수는 플레이어 승리와 분리합니다. 30일의 대기 기간 후 빈 입지가 있으면 새로운 투자자 기수의 재진입이 가능합니다.
- 판매 점유율·이익 유지 또는 기기 수·기업가치에 따른 성장 목표. 기간 평가 후 계속 플레이와 처음부터 자유 경영을 지원합니다.
- 중요 사건은 선택할 때까지 자동 정지. 민원은 클릭 가능한 하단 알림에 표시됩니다.
- 제조: 공정 기술 취득→5일 건설→원자재 발주/입고→생산직 고용→생산 지시→완제품. 인력 없는 생산은 정지하며 급여·유지비를 실제 지급합니다. 자재·미집행 연구비·건설·배송·완제품은 자산이며 인수/합병/청산에 연결됩니다.
- 증권: 회사/제조사 주식 각 1,000주, 제한된 유통량과 거래 상대 현금, 매수/매도 차이, 기업가치에 따른 종가, 현금으로 지급하는 배당. 제조사 이익은 실제 공급 주문에서 발생하며 인수·파산·재진입에 주주 권리를 연결합니다.
- 신도시 입찰: 개발 분담금 $750로 6개 입지 개방, 전액 예치, 상위 입찰 시 환급, 기한에 낙찰. 경쟁사도 입찰합니다. 새 규칙의 낙찰은 입지만 취득하며 기기 구매·설치가 별도로 필요합니다.
- 기한: 아이스크림 8일, 핫 음료 12일, 기타 30일. 동일 상품 혼합 시 가장 빠른 기한 적용. 창고·기기·운송 재고의 만료를 원가 손실로 처리합니다.
- 장기 AI: 30일 가격/손익/상품 이익 기억과 7일 분석, 제조 투자, 적자 경쟁사 기업 합병. 실제 자금과 창고·부채 조건을 충족해야 실행합니다.
- 지연 사건 4종: 공급 중단, 규제 점검, 직원 이직, 신용 재심사. 선택에 따라 3일 후 배송·현금·평판·직원·신용에 영향. 예정된 후속 조치는 운영 규정 메뉴에서 확인합니다.
- 계약·회복: 30/60일 임대 협상과 갱신/해지, 담보 금리 할인, 연체 통지·유예·담보 처분. 창고·생산·설비·주식 청산을 직접 실행할 수 있습니다.
- 자동화: 최소/목표 재고, 원가 가산 가격, 직원 담당 지역, 정비 기준, 현금 유보/자동 상환, 제조 라인 우선 조달. 원래의 실제 직원 이동 시간을 유지합니다.
- 결과: 자진 사업 종료, 음료/기기 공장·생산량·보유 기기·흑자 유지에 따른 산업 지배, 생산/폐기/배당/이자/최고 가치 통계.

## 화면과 조작

상단 상태바·좌측 회사 메뉴·중앙 작업 화면·하단 기록을 사용하는 고정형 경영 UI입니다. 기기 관리에서는 지도와 상세를 함께 보고, 발주·재무·경쟁 등은 중앙 화면에서 전환합니다. 긴 내용은 패널 내부에서 스크롤합니다.

시작 화면과 게임 중 메뉴는 별개입니다. 시작 화면에는 닫기 버튼이 없으며 새 게임/이어하기로 진입합니다. 게임 메뉴를 닫으면 진행 중이던 상태로 돌아갑니다.

첫 접속은 브라우저 언어를 참고하며 저장된 선택과 `?lang=ja` / `?lang=ko` 링크를 지원합니다. 시작·설정·대화창 맨 위에서 한국어/日本語를 바로 선택합니다. 1배속 하루 3분, 0.5/2/4배속. 메뉴·다른 브라우저 탭에서는 시간이 멈춥니다.

## 저장 호환성

기존 저장 키와 핵심 v5 구조를 유지하고 `saveVersion=7`, `enterprise.industry.version=1`, `enterprise.expansion.version=1`을 사용합니다. 기존 회사 수·현금·재고는 유지합니다. 이전 전 원본을 별도 로컬 저장 키에 백업하고 신규 필드를 검증합니다. 예전 기업 규칙 전환 대상 저장의 하루가 진행 중이면 그날은 기존 규칙으로 마친 뒤 다음 날부터 새 기업 운영 규칙을 적용합니다.

8.0.0의 새 게임은 `enterprise.chain.version=1`을 추가합니다. 기존 저장은 종전 조달·생산 규칙을 유지하며, 게임 중 메뉴의 **조달·고용 규칙 적용**을 눌러 새 규칙으로 전환합니다. 전환 직전 저장을 별도 로컬 키에 백업하고 기존 자산과 고용을 이전합니다.

새로운 다회사 저장은 당일 고객·주문·배송·협상도 이어집니다. 초기 회사 수를 바꾸려면 새 게임을 시작해야 합니다.

## 검증과 현재 범위

`npm test`는 13개 묶음으로 기존 저장 회귀와 신규 조달·연구·직원 연결을 구분해 검사합니다. `npm run test:balance`는 기존 6조건 최대 365일, 이전 확장 3난수 × 120일, 새 조달/연구/고용/생산 3난수 × 120일을 실행합니다. 후반 시스템 표본은 초기 자금을 늘린 안정성 검사이며 체감 난이도 보정이 아닙니다. 모델별 온도·교체/개조·독립 사업장 팀·연구 시제품 등 남은 범위는 개발 현황에 표시합니다.

로컬 브라우저 검사는 Playwright와 Edge가 있는 환경에서 `GAME_URL`을 실행 중인 로컬 서버 주소로 설정하고 `npm run test:browser`로 실행할 수 있습니다. 기본 주소는 `http://127.0.0.1:8765/`이며 `BROWSER_EXECUTABLE`로 실행 파일 경로를 바꿀 수 있습니다. Playwright는 일반 게임/CI 필수 의존성이 아닙니다. 필요하면 별도 도구 디렉터리에 설치한 뒤 `NODE_PATH`로 연결합니다.

개발용 조작 화면은 `?debug=1`로만 표시됩니다. 자금 투입·하루 진행·강제 사건·저장 검사 등을 사용하면 해당 저장은 시험 실행/자유 경영으로 표시됩니다. 일반 공개 화면에서는 개발 지침을 표시하지 않습니다.

공개본의 생산·회계 기능은 연결되어 있지만, 제조·수직계열화의 원래 성장 구조는 부분 구현입니다. 외부 음료/기기 회사 조달 → 협력사 투자·기간형 연구 → 자체 공장·인력 운영의 [개편 설계](docs/SUPPLY_CHAIN_DESIGN.md)를 수치 밸런싱보다 먼저 적용합니다. 직원은 현재 회수/보충 인원 카운터이며 직무·숙련·사업장 처리 능력 연결이 남아 있습니다. 실제 구현/검사/공개 상태는 DEVELOPMENT.md를 기준으로 확인합니다.
