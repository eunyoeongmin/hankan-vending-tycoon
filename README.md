# 한 칸 상회 · ハンカン商店

한국어/일본어와 USD를 지원하는 독립 실행 HTML 자판기 회사 경영 게임입니다. 외부 API나 서버 없이 실행하며 저장은 현재 브라우저에 남습니다.

- 공개 게임: https://hankan-vending-tycoon.eym7443.chatgpt.site
- 공개 소스: https://github.com/eunyoeongmin/hankan-vending-tycoon
- 개발 방향·구현 이력·검증 한계: [DEVELOPMENT.md](DEVELOPMENT.md)
- 현재 완료 체크·부분 완료·미착수·다음 작업은 위 상태표를 기준으로 확인합니다. [과거 기록과 사용자 기획 원문](docs/DEVELOPMENT_HISTORY_2026-09-10.md)은 별도 보관합니다.

## 실행과 개발

Python 3.10 이상, Node.js 24, Git이 필요합니다.

```sh
git clone https://github.com/eunyoeongmin/hankan-vending-tycoon.git
cd hankan-vending-tycoon
npm ci
python build.py
npm test
npm run test:balance
python -m http.server 8080 --directory dist
```

http://localhost:8080 을 열거나 `dist/index.html`을 직접 열어 플레이합니다. 저장은 브라우저와 접속 주소별로 분리됩니다. GitHub에는 사용자의 저장 데이터가 올라가지 않습니다.

`src/`가 수정 원본이며 `build.py`가 엔진과 UI를 합쳐 `dist/index.html`을 만듭니다. 상위 작업 폴더에는 `vending-tycoon.html`과 개발 메모 사본도 생성합니다. `dist`를 직접 수정하지 마세요.

- `base.html`: 기존 게임·지도·장면·단일 시계
- `enterprise.js`, `market.js`: 상품·슬롯·재고·회계·고객 시장
- `rivalry.js`, `scenario.js`, `trade.js`: 전략·시작 조건·기기 협상
- `industry.js`: 회사별 자원·공통 조달/금융/계약·다회사 고객·기업 인수·진입/퇴출
- `workspace.js`, `office.js`, `industry-ui.js`: 고정 경영 화면과 회사 메뉴

GitHub Actions는 빌드와 회귀·장기 시뮬레이션 검사를 실행합니다. `.openai/hosting.json`은 기존 공개 사이트 연결 정보이며 로컬 실행에는 인증이 필요하지 않습니다. 배포 인증 정보는 저장소에 포함하지 않습니다.

## 경영 시스템

- 4상권·24입지. 새 게임에서 경쟁 회사 1/2/3곳과 회사당 초기 기기·현금, 사건 빈도, 공급 위험, 경기·물가·공격성·운영 능력 등을 선택합니다. 입문·표준·도전·극한 프리셋, 기간 평가 또는 자유 경영을 제공합니다.
- 기기별 4슬롯, 상품·가격·브랜드·용량·상태. 상품 변경 시 기존 재고는 창고로 돌아갑니다.
- 공통 시장의 각 고객이 플레이어 또는 경쟁사 중 한 곳에서 구매하거나 구매를 포기합니다. 실제 재고 차감·매출·원가가 회계와 구매 장면의 기준입니다.
- 모노벤드·아틀라스 유통·노바 드링크가 독립 현금·재고·주문·배송·작업·임금·연구·브랜드·부채를 운영합니다. 회사마다 상품·가격/광고·투자 정책이 다릅니다. 같은 상권의 NPC끼리도 경쟁합니다.
- 지역 도매(1일/최소40), 공장 직거래(2일/최소100), 특급 공급(0.25일/최소20). 발주 대금을 즉시 지불하고 운송·창고·기기 재고의 가치를 유지합니다. 판매 시 평균 매입 원가를 비용으로 인식합니다.
- 자동 발주, 직원 회수·보충, 물류·품질 투자, 자체 브랜드, 예방 정비. 긴급 매입은 기본 원가 지수의 125%입니다.
- 공급 계약: $15 계약금, 30일 단가 고정과 공급처 제한, 중도 해지 $5. 입지 계약: 기본 임대료 3일분 계약금, 30일 임대료 15% 할인·고정. 회사마다 동일한 계약 함수를 사용합니다.
- 맞불 할인·단골 확보·방어 광고, 경쟁사 공세 예고와 투자/철수 로그. $20 시장조사는 조사 당시 재무 상태 등급·매출 추세를 제공합니다.
- 기기 인수와 매각은 금액 제안·거절/재제시·계약을 거칩니다. 기업 전체 인수에서는 실제 자산·기술·현금·부채를 승계합니다. 일반 경쟁 화면에는 상대의 정확한 재무를 표시하지 않으며, 인수 계약 검토에서 승계 금액을 확인합니다.
- 은행: 자산/신용 기반 대출, 최대 원금 $1,000, 신용에 따른 일 이율, 60일 만기·조건부 연장. 자금난이 7일 이상이고 회복 여력이 없을 때 파산합니다. NPC도 대출과 자산 처분을 먼저 검토합니다.
- 경쟁사 철수는 플레이어 승리와 분리합니다. 30일의 대기 기간 후 빈 입지가 있으면 새로운 투자자 기수의 재진입이 가능합니다.
- 판매 점유율·이익 유지 또는 기기 수·기업가치에 따른 성장 목표. 기간 평가 후 계속 플레이와 처음부터 자유 경영을 지원합니다.
- 중요 사건은 선택할 때까지 자동 정지. 민원은 클릭 가능한 하단 알림에 표시됩니다.

## 화면과 조작

상단 상태바·좌측 회사 메뉴·중앙 작업 화면·하단 기록을 사용하는 고정형 경영 UI입니다. 기기 관리에서는 지도와 상세를 함께 보고, 발주·재무·경쟁 등은 중앙 화면에서 전환합니다. 긴 내용은 패널 내부에서 스크롤합니다.

시작 화면과 게임 중 메뉴는 별개입니다. 시작 화면에는 닫기 버튼이 없으며 새 게임/이어하기로 진입합니다. 게임 메뉴를 닫으면 진행 중이던 상태로 돌아갑니다.

첫 접속은 브라우저 언어를 참고하며 저장된 선택과 `?lang=ja` / `?lang=ko` 링크를 지원합니다. 시작·설정·대화창 맨 위에서 한국어/日本語를 바로 선택합니다. 1배속 하루 3분, 0.5/2/4배속. 메뉴·다른 브라우저 탭에서는 시간이 멈춥니다.

## 저장 호환성

기존 저장 키와 핵심 v5 구조를 유지하고 `saveVersion=6`, `enterprise.industry.version=1`을 추가합니다. 기존 회사 수·현금·재고는 유지합니다. 이전 전 원본을 별도 로컬 저장 키에 백업하고 신규 필드를 검증합니다. 기존 저장의 하루가 진행 중이면 그날은 기존 규칙으로 마친 뒤 다음 날부터 새 기업 운영 규칙을 적용합니다.

새로운 다회사 저장은 당일 고객·주문·배송·협상도 이어집니다. 초기 회사 수를 바꾸려면 새 게임을 시작해야 합니다.

## 검증과 현재 범위

`npm test`는 11개 회귀 묶음으로 시장 거래·자산 보존·저장 재현·다회사 계약과 인수·메뉴·언어·시계·버튼 안정성을 검사합니다. `npm run test:balance`는 표준/도전 × 방치/안정 운영/확장을 고정 난수로 최대 365일 진행합니다. 이는 자동 시뮬레이션 표본이며 인간 플레이로 난이도가 보정되었다는 뜻은 아닙니다.

제조 공장·수직계열화·주식시장·NPC 간 기업 합병·새 도시·입찰·새 지연 사건 큐는 아직 구현하지 않았습니다. 회사별 운영 정책과 확장 보상은 장기 균형 조정 대상입니다. 세부 한계와 다음 과제는 DEVELOPMENT.md에 계속 기록합니다.
