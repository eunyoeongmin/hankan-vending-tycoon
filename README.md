# 한 칸 상회 · 기업 경영판

한국어/일본어, USD 통화의 독립 실행 HTML 경영 게임입니다. 외부 API나 서버 없이 실행되며 자동 저장은 현재 브라우저에 남습니다.

## 빌드와 검증

- `python build.py`: `src/base.html`, `src/enterprise.js`, `src/rivalry.js`, `src/scenario.js`, `src/market.js`, `src/trade.js`, `src/enterprise.css`를 합쳐 `dist/index.html`과 작업 폴더의 `vending-tycoon.html`을 생성합니다.
- Node 24에서 `npm install` 후 `npm test`로 고객·재고·회계·시간·버튼 회귀 검사를 실행합니다.
- 배포 대상은 `dist`입니다. HTML 파일을 직접 열어서도 플레이할 수 있습니다.

## 경영 시스템

- 기기별 4슬롯: 상품·가격·자체 브랜드 설정. 품목 변경 시 남은 재고를 창고로 반환합니다.
- 고객은 가격 민감도, 상품 선호, 날씨·계절, 기기 상태, 품질·브랜드와 경쟁사를 고려합니다. 구매 기록이 재고·매출·화면 속 구매 장면의 공통 기준입니다.
- 지역 도매(1일/최소40), 공장 직거래(2일/최소100), 특급 공급(0.25일/최소20). 원가 지수와 공급처가 매입가에 반영됩니다.
- 발주 대금은 즉시 현금에서 지불합니다. 운송 중 재고와 창고 재고는 자산이며, 기기에 보충해도 추가 비용으로 처리하지 않습니다. 판매 시 실제 평균 매입 원가를 비용으로 인식합니다.
- 긴급 매입은 기본 원가 지수의 125%이며 공급 부족을 메웁니다. 자동 발주와 직원 보충을 함께 쓰면 운영 자동화가 가능합니다.
- 품질·물류 투자, 상권별 광고, 자체 브랜드, 기기 마모·정비를 제공합니다.
- 상권별 유한 고객이 가격·상품·거리·상태·브랜드에 따라 양사 중 한 곳에서 구매하거나 포기합니다. 경쟁사도 실제 재고·발주·배송·보충·회수·임금·정비로 운영하며 실제 판매만 매출이 됩니다. 양사 구매 기록을 장면에 표시합니다. 예상 수익은 출점 판단에만 사용합니다.
- 기기별 구매 실패 원인, 상품별 매출총이익, 최대60일 결산 보관 및 최근 자금 이동을 제공합니다.

## 저장과 호환성

기존 v5 저장에 `enterprise`와 기기별 `slots`를 추가합니다. 기존 날짜·현금·재고·진행 중 영업은 유지합니다. 최초 이전 전 저장을 별도 로컬 저장 키에 백업합니다. 추가 상태도 로드 검증에 포함합니다.

1배속 하루3분과 0.5/2/4배속은 유지합니다. 메뉴·다른 탭에서는 시간이 멈춥니다. 버튼은 실시간 화면 갱신 중 재생성하지 않습니다.

## 모델의 범위

자판기 유통 회사에 집중한 경제 모델입니다. 제조 공장, 주식시장, 다업종 그룹 경영은 포함하지 않습니다. 기존 이벤트의 비용·보상과 연구·민원 처리도 결산에 반영합니다. 기업 경영판의 결산은 실제 상품 원가 및 광고·정비·본사 비용을 포함하며, 보상 수입은 기타 순비용에서 차감합니다.
## 언어 진입과 경쟁 전략 확장

- 첫 접속은 브라우저의 선호 언어 목록에서 한국어/일본어를 찾습니다. 저장된 언어 선택이 우선하며 `?lang=ja` / `?lang=ko` 링크로 바로 시작할 수도 있습니다.
- 시작·설정·도움말 등 대화창 맨 위에 항상 `한국어 / 日本語` 전환 버튼을 표시합니다.
- 경쟁 전략 화면에 양쪽 회사의 예상 선택률과 경쟁 행동·전황을 표시합니다. 상대 실제 현금·손익·자금 부족 횟수는 내부 계산에만 사용합니다. 공통 시장의 실제 구매가 양쪽 재고와 손익에 반영됩니다.
- 플레이어는 상권별 맞불 할인(3일, 실제 결제 가격 15% 할인), 단골 확보(5일), 방어 광고(3일) 중 하나를 운영합니다. 비용은 현금과 손익에 반영하며 중복 적용을 막습니다.
- 경쟁사는 하루 전 공세를 예고하고, 기간과 자금 제약 안에서 가격·광고 전략을 사용합니다. 현금이 부족하면 공세를 취소하고 기기를 처분합니다. 자금 부족이 5일 연속 지속되면 철수합니다. 철수는 성과로 기록되며 게임은 계속됩니다.
- 상대는 자금난에 빠진 플레이어에게 인수 제안을 보낼 수 있습니다. 플레이어 기기의 매각은 직접 수락해야 실행됩니다. 플레이어의 파산·은행 엔딩 규칙은 유지합니다.

## 시작 조건과 개발 메모

새 게임에서 입문·표준·도전·극한 프리셋과 9개 세부 조건을 선택합니다. 선택은 게임별로 저장되며 현재 게임 설정에서 조회할 수 있습니다. 기존 저장의 규칙은 유지합니다. 설정 난도 지수는 표준100인 자체 참고값입니다.

구현 상태·설계 결정·미완료 과제·검증 결과는 [DEVELOPMENT.md](DEVELOPMENT.md)에 계속 기록합니다. 빌드 시 작업 폴더의 `자판기_개발메모.md`에도 복사합니다.

## 공통 시장 첫 단계와 메뉴 수정

플레이 중 게임 메뉴에서 닫고 복귀할 수 있으며 수동 일시정지는 유지합니다. 첫 접속의 시작 화면에는 닫기 버튼이 없습니다.

`enterprise.operations`에 경쟁사 재고·주문·작업·고객 진행을 저장합니다. 이전 저장은 최초 이전 전 별도 키에 백업하고, 이미 시작한 당일 영업은 기존 판매 기록을 보존한 채 마친 다음 날 공통 시장으로 전환합니다. 초기 NPC 재고는 기기당60개를 개시 재고로 부여하며 현금은 유지합니다. 이후 신규 출점은 빈 기기로 시작합니다.

현재 경쟁사는1곳이며 운영 정책은 자동입니다. 공통 고객 거래를 구현했지만 회사별 연구·대출·계약·협상과 다수 회사 모델까지 동일한 범용 기업 엔진으로 통합한 상태는 아닙니다. 경쟁 화면의 선택률은 여전히 예상값입니다. 30일 자동 검사는 실행 안정성을 확인하며 장기 밸런스를 보증하지 않습니다.

## 다른 환경에서 개발하기

Python 3.10 이상, Node.js 24, Git이 필요합니다.

```sh
git clone https://github.com/eunyoeongmin/hankan-vending-tycoon.git
cd hankan-vending-tycoon
npm ci
python build.py
npm test
python -m http.server 8080 --directory dist
```

브라우저에서 http://localhost:8080 을 엽니다. Python 명령이 `python3`인 환경은 명령을 바꿔 실행하세요. 서버 없이 `dist/index.html`을 직접 열 수도 있습니다. 저장은 브라우저와 접속 주소별로 분리되며 GitHub에 게임 저장 데이터는 올라가지 않습니다.

`src/`가 수정 원본, `tests/`가 자동 검사, `DEVELOPMENT.md`가 개발 방향과 미완료 작업입니다. 수정 후 빌드·검사를 실행하세요. 빌드 시 상위 폴더에도 독립 HTML과 개발 메모 사본을 생성합니다. GitHub Actions는 빌드와 테스트만 실행합니다.

`.openai/hosting.json`은 기존 공개 게임의 배포 연결 정보이며 로컬 실행에는 인증이 필요하지 않습니다. 자신의 사이트에 배포할 때는 자신이 관리하는 호스팅을 사용하세요. 이 저장소에는 배포 인증 정보를 포함하지 않습니다.

## 시작 화면과 플레이 메뉴

첫 접속의 시작 화면에는 새 게임·이어하기·언어 설정을 유지하며 닫기 버튼은 없습니다. 플레이에 진입한 뒤 여는 게임 메뉴는 닫기·저장·설정·도움말·시작 화면 복귀를 제공합니다. 시작 화면 복귀 중에도 영업은 멈추며, 이어하기로 다시 들어갑니다.

## 기기 인수 협상

경쟁사 기기를 선택해 인수 협상을 열고 USD 금액을 제안합니다. 상대는 거절·역제안·수락으로 응답하며, 수락 후 계약 체결을 눌러야 금액과 실제 기기가 이전됩니다. 협상당 제안은3회이며 당일 조건만 유효합니다. 기기별 새 협상으로 전환할 수 있고, 같은 협상을 닫거나 저장 후 불러와도 제안 상태는 유지됩니다. 상대의 마지막 기기는 더 높은 희망가를 요구합니다.

## 한 화면 경영 UI

지도와 핵심 지표를 유지하면서 옆 패널의 탭으로 기기 관리·발주·재무·직원·연구·시장·경쟁·알림·일지를 엽니다. 작은 화면에서는 패널이 지도 아래에 배치됩니다. 페이지 전체 대신 패널 내부에서 긴 내용을 스크롤합니다. 지도에서 기기를 선택하면 관리 탭으로 돌아옵니다. 지도 아래 품절·민원·사건 버튼으로 관련 화면에 접근합니다.

레이아웃 원본은 `src/workspace.js`와 `src/workspace.css`이며 `build.py`에서 기존 엔진 뒤에 결합합니다. 자동 UI 경로 검사는 `tests/workspace.cjs`입니다.

## 고정형 경영 콘솔

현재 UI는 상단 상태바·좌측 회사 메뉴·중앙 작업 화면·하단 영업/경쟁사/민원 기록으로 구성됩니다. 기기 관리에서는 지도와 상세를 함께 보고, 재무·발주 등에서는 작업 화면 전체를 사용합니다. `src/office.js`와 `src/office.css`가 이 구성을 담당합니다. 경제 규칙과 저장 형식은 동일합니다.
