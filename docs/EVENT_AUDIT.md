# 선택 사건 구현 대조 · 10.3

2026-09-11. 기존 20종을 새 운영 규칙에 맞춰 재설계하고 20종을 추가했다. 10.2.1 당시 미완료 기록은 [이전 대조](EVENT_AUDIT_10.2.1.md)에 보존한다.

## 공통 처리

발생 → 대상 ID/견적/3일 응답 기한 고정 → 선택 또는 보류 → 실제 지출·작업·효과 → 결과 이력/후속 사건 순서다. 같은 종류는 45일 재발 대기, 결정 후 최소 5일 간격이며 난이도의 사건 빈도를 따른다. 조건 없는 공장·직원·대출 사건을 초반부터 강제로 표시하지 않는다. 보류는 영업을 계속하며, 미응답은 유료 제안을 자동 수락하지 않는다. 고장·공급 차질·계약 만료 등 원인이 남는 사건은 만료 결과가 적용된다.

매력 배수는 실제 고객 선택 점수에 적용된다. 광고가 판매·현금을 직접 생성하지 않는다. 행사 방문은 다음 날 생성하는 공통 고객 풀에 적용되어 당일 이미 생성한 고객 수는 바꾸지 않는다. 가격 변화는 실제 결제에, 원가 변화는 신규 주문에 적용한다. 고정 구매/차입 계약은 유지한다. 행사 이력의 매출은 효과 적용 중 실제 매출이며 증분 매출 추정치가 아니다.

## 비용·자산·저장 범위

- 화면 표시는 USD, 내부 기존 회계 단위 1000 = $1 유지. 기본 견적은 해당 상권 보유 대수의 제곱근(1~6배)이며 발주/보증금/원금/연구 추가금은 실제 견적 사용. 비용이 바뀌면 새 견적을 보여주고 다시 결정한다.
- 경쟁사는 실제 현금·판매 재고·창고 여력·고용 가능 여부를 충족해야 참여한다. 후원권 예치금은 결과 전 자산으로 보유, 패찰 시 전액 반환한다.
- 외주 마무리는 자사 생산 작업의 재료 가치·수량을 넘긴다. 수령 창고가 없거나 가득 차면 화물을 보유한 채 입고를 기다린다. 무에서 완제품을 추가하지 않는다.
- 신규 배치는 분할·도매·배송·거점 이동 후에도 lot을 보존한다. 회수는 회사별 보관/기기/도매 운송/배송/거점 이송 화물을 포함한다. 판매 완료분은 회수할 수 없다. 과거 저장에서 이미 합쳐진 서로 다른 배치의 원래 계보는 복원할 수 없다.
- 은행의 새 고정/변동 조건 선택: 변동은 최초 연 -0.5%p, 사건 시 해당 계약만 변경. 회사채·기존 저장 계약은 기본 고정. 상환 기간은 기존 규칙 유지.
- `businessEvents` 저장 확장에 견적·대상·효과·작업·결과를 보관한다. 확장 없는 과거 저장은 그대로 로드한다. 구 규칙 저장은 기존 20종을 유지하며, 장기 경영 전환 후 새 사건을 사용한다. 불러온 시점에 이미 떠 있던 구 사건은 구 처리로 마친다.

## 구현과 검사 근거

- `src/business-events-{catalog,core,choices,actions,hooks,ui}.js`: 40종 명세, 대상/견적, 선택 실행, 시스템 효과, 사건 장부.
- `src/reference-commerce.js`, `src/reference-core.js`: 도매 화물의 배치 계보 유지. `src/reference-market.js`: 실제 선택/결제/판매 보류.
- `tests/business-events.cjs`: 80개 선택, 선택 전 저장 재개, 지연 결과, 중복/현금 부족/기한 만료, 경쟁사 자금, 회수·차환·수리·창고 여력·오류 저장.
- `tests/business-events-long.cjs`: 빈번한 사건과 보류를 섞는 2난수 × 365일 실제 운영 검사. 별도 추가 자금 표본으로, 난이도 평가가 아니다.
- `tests/browser-business-events.cjs`: 실제 선택 버튼과 금전·샘플 차감, KO/JA, 보류 저장 재개, 단일 시계, 4화면 크기.
- 실행 결과와 공개 상태: [개발 현황](../DEVELOPMENT.md), [검사 기록](VALIDATION_10.3.0.md).

## 명시적 단순화와 남은 검증

운송사는 외부 경제 풀과 생산 여력으로 표현하며 별도 독립 회사 AI가 아니다. 냉장 대체편은 지연·비용·보호 상태로 표현하며 추가 차량의 개별 경로 애니메이션을 만들지 않는다. 재고 차이는 선택에 따른 실사 완료 시 실제 남은 배치에서 최대 2개를 정정한다. 시제품 사건은 품질 연구에 한정한다. 원작의 모든 산업 사건을 복제하지 않는다.

선택과 자산 흐름 구현 완료와 인간 플레이 재미·사건 빈도·ROI 균형 완료는 별개다. 인간 플레이 기반 밸런싱은 미완료 상태로 유지한다.
