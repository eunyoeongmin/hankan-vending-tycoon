## 검증 방법과 한계

`tests/browser-level-audit.cjs`는 실제 브라우저 버튼으로 업무 창을 열고 마지막 활성 작업까지 스크롤한다. 많은 기기 상태는 실제 구매·시간 경과로 성장한 회사가 아니라 `npcMachine`·`refInitializeMachine`으로 만든 **화면 부하 fixture**다. 경쟁사 소유 기기를 제거하고 모든 현재 입지에 플레이어 기기를 넣으므로 경쟁·수요·재무의 유효한 플레이 표본으로 사용하지 않는다.

- 변경 전 176개 업무 조합 및 창 생명주기 자동 검사 통과.
- 변경 전 실제 캡처: 다상권 일본어 모바일 보유 기기, 한국어 PC 재무를 눈으로 확인. 도시 유지·창 분리 확인, LV-01 식별.
- 최종 통합 빌드: 176개 업무 조합 재통과. 8개 단계/언어/화면 조건에서 비서 질문 패널을 열어 업무 본문 높이·가로 넘침·닫기/최소화 버튼 접근 확인, 회사 목표 창 열기 확인. 일본어 390px 상담·회사 목표·24대 보유 목록 캡처를 눈으로 확인. 판정은 자동 브라우저+캡처 검토이며 인간 첫 플레이와 구분.
- 최종 캡처는 `artifacts/level-audit/`에 로컬 보관. 테스트 재실행으로 생성 가능하며 공개 게임 자산에 포함하지 않음.
- 사람의 첫 플레이, 임의 저장에서 발생한 원래 설치 실패, 24대를 실제 운영하는 경제성, 추가 도시의 혼잡 자연스러움은 미검증.
- 초기·확장·직원/제조/연구·경쟁·파산/승리/계속 운영의 설명 연결은 Narrative/Game 담당의 결과와 함께 대조해야 하며, 이 문서의 UI 순회 통과로 대체하지 않음.
