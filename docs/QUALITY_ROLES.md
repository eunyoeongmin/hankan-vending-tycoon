# 멀티에이전트 공통 운영 지침

## 적용 범위와 기준 문서

사용자가 지정한 두 담당은 **게임 시작부터 후반·엔딩까지 전체 게임**을 책임진다. 이번 작업을 작은 단위로 나누더라도 역할 자체를 초반 실습이나 개별 기능으로 축소하지 않는다. 자유 경영의 장기 운영, 위기 회복, 승리·파산 및 계속 플레이도 포함한다. 실제 종료 구조가 없거나 불명확하면 미구현/설계 공백으로 기록한다.

저장소의 `game-agent.md/`가 지침의 기준 위치다. 사용자 작업 폴더의 동명 폴더에도 개정본을 반영했으며, 이후 변경은 저장소 기준으로 관리한다. 이 지침은 개발 작업에 적용하며 게임 화면에 노출하지 않는다. 상시 실행되는 서비스나 영구 기억을 뜻하지 않는다. 다음 세션은 문서와 기록을 읽어 이어간다.

| 담당 | 필독 문서 | 전체 책임 |
|---|---|---|
| 튜토리얼·플레이 경험 | [Game](../game-agent.md/game-designer.md), [Narrative](../game-agent.md/narrative-designer.md), [Level](../game-agent.md/level-designer.md) | 모든 기능의 학습 시점·조작·대화·결과 인지·실패와 복구·후반 안내 |
| 밸런스·시스템 | [Economy](../game-agent.md/economy-designer.md), [Game](../game-agent.md/game-designer.md) | 경제·은행·성장·직원·조달·제조·연구·경쟁·사건·승리와 파산 |
| 통합 | 네 문서 모두 | 범위 설정, 설계 충돌 조정, 구현·화면·저장 호환·회귀 검사·공개 상태 기록 |

## 배정과 협업

1. 통합 담당은 사용자 목표와 DEVELOPMENT.md의 현재 상태를 확인한다. 여러 시스템을 잇는 개발·종합 점검은 두 담당에게 독립적으로 실행 가능한 범위를 배정한다. 사소한 문구 변경마다 모든 에이전트를 동원하지 않는다.
2. 각 작업에는 대상 시스템/성장 단계, 조사할 질문, 수정 가능한 파일, 완료 조건과 산출물을 명시한다. 같은 파일의 동시 편집을 피한다. 읽기·분석 작업과 구현 작업을 구분한다.
3. 담당자는 본 작업 밖에서 발견한 문제도 미점검/후속 항목으로 남긴다. 전체 역할을 맡았다는 이유만으로 조사하지 않은 시스템을 통과 처리하지 않는다.
4. 설계 문제와 설명 문제를 교차 검토한다. 은행이라면 밸런스 담당이 투자·상환의 성립을, 튜토리얼 담당이 비용과 위험의 이해·조작을 확인한다. 설명을 늘려 잘못된 경제 구조를 덮지 않는다.
5. 통합 담당이 결과를 검토하고 필요한 검사를 마친 후 반영한다. 커밋·공개 반영은 통합 담당이 일관되게 관리한다. 되돌릴 수 있는 일상 구현 선택은 기존 사용자 승인 범위에서 진행한다.

## 공통 결과 보고

각 발견에 다음을 기록한다.

- 식별자, 담당, 대상 시스템과 성장 단계.
- 코드/저장/시드/난이도/자동화/배속 등 재현 조건.
- 관찰 사실과 증거, 플레이어 영향, 원인 가설을 분리.
- 분류: 기능 오류 / 경제 붕괴 / 학습·가독성 문제 / 수치 조정 후보 / 미구현·미점검.
- 최소 수정안, 연결 시스템 영향, 실제 변경 파일.
- 수정 전후 결과와 남은 불확실성.

단계별 완료 여부는 `미점검 → 조사 중 → 문제 확인 → 수정 → 검증`으로 관리한다. 근거상 문제가 없으면 조사 조건을 붙여 검증으로 기록한다. 코드 검사, 실제 화면 확인, 인간 첫 플레이, 공개 반영은 서로 다른 증거이며 한 상태로 뭉치지 않는다. 작업량이 크다는 이유로 미점검을 완료로 바꾸지 않는다.

## 게임 전체 점검표

다음 영역 모두에 두 담당의 관찰과 검증 근거가 필요하다. 표는 책임 범위이며 현재 완료를 뜻하지 않는다. 실제 진행 상황은 DEVELOPMENT.md와 연결된 검토 문서에서 관리한다.

| 영역 | 튜토리얼·플레이 경험 질문 | 밸런스·시스템 질문 |
|---|---|---|
| 시작·기본 영업 | 조건·시간·판매·회수를 이해하는가? | 시작 조건과 운영자금, 첫 수익까지 시간이 성립하는가? |
| 발주·물류·출점 | 입고와 보충, 구매와 설치를 구분하는가? | 재고·기간·능력·비용이 확장과 연결되는가? |
| 은행·재무 | 금리·지급 예정액·상환·연체를 판단할 수 있는가? | 투자 회수·만기·현금흐름·회복 가능성이 맞는가? |
| 직원·연구·제조 | 채용·배치·투자·성과·생산을 실제로 수행할 수 있는가? | 급여·처리 능력·투자 회수·외부 조달과의 선택이 성립하는가? |
| 경쟁·사건·위기 | 상황·선택 대가·대응 결과를 이해하는가? | 상대 자원과 행동, 대가·혜택, 위기와 회복이 합리적인가? |
| 후반·종료·계속 | 다음 목표와 승리·파산 원인, 계속 운영을 이해하는가? | 지배 전략·성장 한계·최종 목표와 장기 운영이 의미 있는가? |

## 현재 검증 범위

10.6.2까지의 담당별 검토는 기본 실습과 제한된 초반 경제 경로에 해당한다. 중후반, 전체 은행 구조, 장기 경쟁, 종료 경험은 별도 검증이 남았다. 이번 지침 개정은 그 작업들을 완료했다는 뜻이 아니다.
