# 튜토리얼·밸런스 담당 검토 기준

사용자가 2026-09-14 요청한 두 담당 역할을 개발 작업에 적용한다. 이는 개발 중 에이전트의 역할 분담이며, 게임 안에서 실행되는 AI나 상시 백그라운드 서비스가 아니다. 다음 개발 환경에서도 이 기록과 DEVELOPMENT.md의 미완료 항목을 이어서 검토한다.

## 튜토리얼 담당

- 첫 만남 → 배우려는 내용 확인 → 플레이어의 시작 선택 → 실제 조작 → 결과 확인 순서를 지킨다.
- 인사와 질문은 짧고 자연스럽게, 실제 실습은 거래 결과로 진행한다. 설명 대화를 넘겼다고 실습을 완료시키지 않는다.
- 대화 중 게임 시간이 흐르지 않아야 한다. 진행 중 저장, 기존 저장, 실습 종료, 한국어/일본어, 작은 화면을 확인한다.
- 조작 대상이 보이지 않거나, 대기 이유가 불명확하거나, 선택 실패 후 복구할 수 없는 지점을 기록한다.
- 자동 검사가 통과해도 첫 플레이 이해도까지 검증했다고 표시하지 않는다.

## 밸런스 담당

- 연습 회사와 자유 경영의 조건을 구분해 현금, 실제 손익, 창고·기기 재고, 미지급금, 출점 비용과 대기 시간을 조사한다.
- 수치마다 코드 근거 또는 재현 가능한 관찰을 남긴다. 한 번의 실행 결과를 평균 난이도라고 표현하지 않는다.
- 진행 불능·자금 복제·무료 공급 같은 붕괴는 우선 수정 대상으로 보고한다. 난이도·성장 속도 조정은 별도 제안으로 구분한다.
- 초반 점검 후 확장 운영, 직원/물류, 제조/연구, 경쟁과 금융을 같은 방식으로 검토한다. 점검하지 않은 영역은 완료로 표시하지 않는다.

## 통합 담당

변경 충돌을 조정하고 실제 화면, 저장 호환, 회귀 검사와 공개 반영을 확인한다. DEVELOPMENT.md에 구현·검사·공개 상태와 남은 문제를 따로 기록한다. 담당자가 쓴 분석만으로 수치나 완료 표시에 자동 반영하지 않는다.
