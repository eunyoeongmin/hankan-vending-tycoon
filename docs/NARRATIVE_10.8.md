# 10.8 Narrative Designer 후속 운영 코치 제안

2026-09-15. 원본 Sites 체크아웃은 읽기만 했으며 이 폴더의 제안 파일과 독립 검사를 작성했다. 통합·브라우저 검증·배포는 root의 책임이다.

## 통합

- `continuing-guide.js` / `.css`를 src에 반영하고 기존 operating-advisor, practical-guide, lifecycle 뒤에 로드한다.
- 외부 API나 별도 타이머 없음. 기존 updateDesk(기존 refreshLiveNumbers 경로)의 상태 관찰과 사용자 클릭에서만 실행.
- DOM `#continuing-guide`를 officeRegister 앞에 삽입. `body.continuing-active`일 때만 하단 210px, 모바일190px 제안. 안내 최대115/95px, 나머지 로그 공간 확보. 최종 실제 화면은 Level 검사 필요.
- 공개 API: `continuingStart(kind)`, `continuingCheck()`, `continuingPaint()`, `continuingState()`.
- 종류: refill, finance, expansion, staff, research, manufacture.
- 선택 상태는 `state.continuingGuide` version1. 활성 과제, 기준 판매/부채/작업/연구 식별자, 완료 기록, 제안 켜기, 2일 미루기를 저장. 잘못된 선택형 데이터는 정규화하며 경제 저장의 유효성을 바꾸지 않는다.
- `continuing-guide.cjs`는 GAME_REPO 환경변수 또는 현재 로컬 경로의 기존 dist/harness에 제안 모듈을 script로 주입한다. 정식 통합 테스트로 옮길 때 이미 로드된 모듈이면 재주입하지 않도록 변경 필요.

## 실제 동작과 제한

| 흐름 | 시작 조건/판정 | 성공 증거 | 복구·제한 |
|---|---|---|---|
| 품절 복구 | 대상 기기의 같은 상품/거점 발주 또는 기존 창고 재고 | 입고→기기 실제 재고/판매→대상 판매 누적 증가 | 소멸된 입고 작업이면 발주 단계로 복귀. 7일 후 재발생 품절은 재제안 가능. 다중상품 전부 보충이 아니라 해당 기기의 판매 재개 목표 |
| 상환 | 기존 원금 계약. 부채 없으면 새 차입 권유 없이 안내 후 시작 거절 | 수락 시 존재했던 계약의 원금 감소 | 일부/예정 상환 모두 인정. 이자만 지급한 경우 완료하지 않음. 상환 가능한 금액 추천은 root 자금계획과 연결 |
| 추가 출점 | 수락 시 기존 입지 목록 기록 | 새 위치 기기 설치→실제 재고→실제 첫 판매 | 단순 구매/화면 클릭으로 완료 안 됨. 자금 부족이면 미루기, 기본 판매실습 재강제 안 함 |
| 직원 배치 | 지원 역할 restock/drink/machine의 정상 배치 직원 | 해당 직원 배송 작업 또는 해당 사업장 생산 작업의 진행값 변화 | 일반 경험치는 시간만 흘러도 증가하므로 성공 기준에서 제외. 인력 급여/퇴직/승진의 전 과정 학습은 아님 |
| 연구 | 현재 미완료 과제 식별자 추적 | 동일 과제 complete | 취소되면 과제 선택으로 복귀. 사용권→신상품 사업화까지 완료했다는 주장 없음 |
| 제조 | 실제 생산 job 존재 | 누적 manufactured 증가 | 공장·원재료·인력 준비 안내. **완제품 생산까지이며 출하/판매/수익학습은 미완료** |

- 화면 이동은 다음 버튼이 아니다. 실제 계약/재고/작업/판매 조건을 만족해야 진전한다.
- 기존에 진행 중인 주문·과제·작업도 받아서 이어간다. 제안은 수락 전 경제 선택을 실행하지 않는다.
- 신규/기존 회사에서 한 번 환영문과 실제 현재 자동 운영 상태를 표시한다. 기본 실습 중에는 숨기므로 완료 뒤 등장한다. 시간·배속·자동화를 켜거나 끄지 않는다.
- 선택적 안내는 일시정지를 강제하지 않는다. 대기 안내에 현재 정지/진행 상태와 상단 재개 위치를 표시한다.
- 한 번에 활성 과제 하나. 미루기/끄기/다시열기 제공. 완료 이후 즉시 다른 제안이 나오지 않도록 2게임일 쿨다운. 같은 과제 다시 수락하면 기준값을 새로 잡는다.
- 현재 회사 state 객체가 바뀌면 선택 목록·강조 클래스 같은 화면 상태를 초기화한다.
- 사용자 클릭 수를 숙련도 또는 학습 완료로 오인하지 않는다. 완료 체크는 목표 성과이며 인간의 이해도를 증명하지 않는다.

## 검증

독립 jsdom 테스트 통과 (2026-09-15):

- 실제 refOrder→refCommerceAdvance 입고→refDispatchRoute→refOperationsAdvance 배송→advanceBusiness 실제 판매.
- 실제 mgBorrow→mgRepay 부분 원금 상환. 화면 이동만으로 미완료.
- 실제 입지 계약→기기 주문→도착→설치→음료 배송→추가 기기 첫 판매.
- 실제 refResearch→companyReceive 진행/검토 승인→연구 완료.
- 실제 공장 건설/도착, 인력 채용, 자체 상품, 원재료 발주/입고, refProduce→공정 진행→완제품 증가.
- 위 생산 과정의 배치 직원 실제 작업 진전 판정.
- 저장 재개(입고 중), 제안끄기 저장, 새회사 완료기록/화면목록 초기화, malformed 선택형 상태 복구, KO/JA, 기본 실습 중 중첩 방지.

금액/빈 재고의 테스트 fixture는 명시적으로 구성했다. 구매·배송·생산·판매 결과는 실제 엔진으로 얻었고 학습 플래그나 판매량을 조작하지 않았다. 장기 대기는 기존 companyReceive/refCommerceAdvance 등 엔진에 큰 dt를 주어 가속했다. 실제 브라우저 클릭/레이아웃·인간 플레이·장기 밸런스 검증과 구분해야 한다.

## 남은 범위

- 사건 40종별 조작 코치, 경쟁 방어/인수 이후 결과 학습, 파산/엔딩별 비서 대화.
- 생산 완제품 출하부터 실제 판매 마진 검증까지 추가 목표.
- 직원 트랙은 배송/생산만 지원. 연구 인력·입출고·정비의 직원별 실작업 증거 확장.
- 다중 과제 선택 시 현재 목표를 교체한다는 추가 UI 설명, 인간 중후반 플레이 검증.

## 추가: 실습 회사에서 시장 변화 선택

실습 시작이 events0/supply0을 유지하여 이후에도 사건이 발생하지 않는 원인을 확인했다. 자동으로 난이도를 바꾸지 않고 다음 선택을 추가했다.

- `state.guide.step>=16`, 현재 사건0/공급0, 유효 시나리오, 기본 실습 비활성일 때만 하단에 현재 상태와 **시장 변화와 함께 운영** 버튼.
- 별도 확인 창 `openModal('continuing-market')`: 사건 없음→보통, 공급 안정→보통, 다음 사건 추첨/신규 발주부터 적용 설명. 유지/닫기 가능.
- 확인 API `continuingApplyMarket()`는 해당 모달 및 자격 조건을 다시 확인하고 validScenario로 검사한다. 시나리오의 events/supply 두 값만 STANDARD_RULES의 값으로 바꾸며 preset custom 지정, 저장/게임 기록 추가.
- 자금/기기/직원/기존 주문·차입·계약/자동 운영/진행·배속/기타 난이도는 변경하지 않는다. 즉시 사건을 일으키거나 진행 중 배송을 지연시키지 않는다.
- 검사 추가: KO/JA 확인 내용, 유지 시 규칙 불변, 확인 시 정확히 두 규칙/preset 변경, validScenario 통과, 운영/거래/자동화/정지/배속 스냅샷 동일, 적용 뒤 버튼 자격 소멸.
- 에이전트 제안 단계에서는 메모리 내 소스 교체로 독립 검사했다. 저장소의 최종 `tests/continuing-guide.cjs`는 management-harness를 사용하여 실제 빌드된 dist 그대로 검사한다. 환영 버튼 클릭 후 노드 재사용으로 시장 확인창까지 열리던 오류는 클릭 시작 시 읽은 단일 분기로 수정했다.
