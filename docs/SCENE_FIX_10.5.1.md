# 10.5.1 거리 화면 수정 — 2026-09-11

## 발견과 수정

10.5는 정지 화면과 투영 좌표를 검사했지만, 공통 도로 위에 물을 덧그리는 구조와 판매 기록마다 인물을 추가하는 구조를 놓쳤다. 기존 300건의 합성 구매 표본에서 86명과 80개 표시가 한 경로에 겹치는 것을 실제 브라우저 캡처로 재현했다.

| 문제 | 수정 | 화면 평가 |
|---|---|---|
| 공통 배경에 강/호수를 덧그려 차도와 충돌 | 상권별 도로·물·철도 배열과 단일 지형 판정 | 강은 도로 사이, 관광지는 해안/호수와 산책로를 분리 |
| 나무·텐트·파라솔·가로등이 물/차도에 놓임 | 지면 위치 수정, 고정 소품의 금지 지형 검사 | 나무의 수관은 물 위에 걸쳐도 줄기는 육지에 위치 |
| 입지별 짧은 단방향 반복 | 화면 밖 출입하는 연결 경로·반대 방향·갈림길 | 중간에서 갑자기 생기는 인물 대신 길을 따라 진입/퇴장 |
| 구매 기록 수만큼 고객 겹침 | 전체 보행자 12명, 기존 행인을 구매자로 전환 | 접근→정지→구매 표시→음료를 들고 퇴장 |
| 마주친 사람끼리 멈춤 | 최소 발 위치 간격과 막힘 시 옆으로 회피, 직원/카트 공간 확보 | 최초 검토에서 발견한 교착을 수정하고 재검사 |

구매 표시는 입지별 판매 기록의 합계다. 300건을 한 손님이 구매했다는 뜻이 아니며, 실제 현금·재고·판매·저장 계산은 그대로다. 새 렌더러는 경제 상태를 읽기만 한다. 본편에 새 타이머를 추가하지 않고 기존 시각 시간으로 이동한다. 상권/저장을 바꾸면 과거 기록을 기준점으로 삼아 재생하지 않는다.

## 검증 근거

- 자동 회귀 `npm test` 23묶음 통과.
- 도시 아트 브라우저 검사 통과: KO/JA·상권/계절·배율/선택 영역 및 지연된 대표 구매 표시.
- desktop/management 브라우저 검사 통과: 업무 창과 도시 동시 표시, 메뉴 구분, 입력 유지, 실제 차입/상환, 저장 재개, KO/JA 및 4개 화면 크기.
- `npm run test:scene`: 5상권 각각 6입지×1,000건 합성 판매 기록, 100ms 간격 1,800회(시각 시간 3분) 검사. 최대 12명, 물/차도 침범 0, 도로/물 형상 교차 0, 모든 입지 구매 표시, 발 위치 최소 약 10px, 최장 막힘 850ms, 경제 상태 JSON 불변.
- 실제 새 게임 1/64/256배 각각 4초: 250ms 표본 최대 이동 약 6.14/6.52/8.05px. 게임 배속에 비례해 인물이 폭주하지 않음. 일시정지 후 캔버스 동일.
- 별도 검사용 페이지의 실제 시간 20초를 녹화하고 4초 간격 캡처, 특히 12/16/20초 접근·구매·퇴장 화면을 열어 비교. 5개 상권 지형 캡처도 검토했다. 영상 전체에 대한 인간 플레이 평가는 아님.
- 로컬 증거: `artifacts/scene-fix/`의 `before-crowd.png`, `final-terrain-*.png`, `motion-*.png`, `live-*.png`, JSON 결과 및 video 폴더. 이 자료는 로컬 검사 산출물이며 Git에 포함하지 않는다.

재현은 Playwright와 Edge가 있는 환경에서 빌드 후 `npm run test:scene`. 임시 `dist/review.html`을 만들고 8766 포트의 격리 서버에서 검사한 뒤 삭제한다. 수동 연속 검토는 `python tests/make-scene-review.py` 후 로컬 서버의 review.html을 열어 재생한다. 검사용 페이지는 배포하지 않는다.

## 남은 범위

도로와 물은 상권별로 다르지만, 두 개의 주 보행로와 연결 분기는 공유한다. 상권마다 완전히 별개의 대규모 보행망을 구현한 것은 아니다. 개별 통근 목적지·일행·신호 대기·모든 실제 고객의 일대일 인물화도 이번 범위가 아니다. 장시간/저사양 성능과 인간이 느끼는 거리의 자연스러움은 추가 평가가 필요하다. 10.5의 기존 통과 기록이 이 문제까지 보장했다는 식으로 해석하지 않는다.
