# 비서·학습·사업 사건 지침

## 책임 범위

인사말 작성에 그치지 않는다. 시작부터 확장, 은행·직원·물류·연구·제조, 경쟁과 위기, 후반 목표, 승리·파산·계속 플레이까지 상황에 필요한 대화와 학습을 맡는다. 실제 구현이 없는 사건·결과·엔딩은 약속하지 않고 설계 공백으로 기록한다.

## 비서의 말투와 역할

- 비서는 사장과 함께 회사를 운영하는 차분하고 친절한 동료다. 상대를 어린아이처럼 다루거나 매 행동마다 과장되게 칭찬하지 않는다.
- 첫 만남은 인사 → 궁금한 점에 대한 응답 → 준비 확인 → 실제 운영으로 연결한다. 인사와 안심시키는 대화도 관계를 만드는 역할이 있다.
- 안내는 필요한 행동과 이유를 짧게 연결한다. 숫자와 위험을 숨기지 않는다. 대출을 권유할 때는 비용·상환 일정을, 품절 때는 현재 원인과 가능한 대응을 알려준다.
- 평소에는 부드럽게, 지급 기일이나 손실 위험이 급할 때는 짧고 명확하게 말한다. 실패를 비난하지 않고 복구 가능 여부를 실제 상태에 맞춰 설명한다.
- 예: “사장님, 이번 달 상환일이 다가와요. 예정된 지출까지 함께 확인해 볼까요?” 실제 일자·금액은 게임 상태에서 가져온다.
- 한국어와 일본어는 같은 의도와 사실을 전달하되 자연스러운 표현을 쓴다. 이미지에 설명 문자를 박아 넣지 않는다.

## 게임 전체 학습

- 새로운 시스템을 처음 사용할 때 필요한 판단과 조작을 가르친다. 모든 설명을 시작 화면에 몰아넣지 않는다.
- 선행 지식, 등장 조건, 설명할 이유, 실제 조작, 성공 판정, 실패·복구, 다시 보기와 생략 가능 여부를 기록한다.
- 은행은 대출 신청에서 끝내지 않고 지급 예정액 확인과 상환까지, 제조는 공장 버튼에서 끝내지 않고 원재료·직원·생산·출하·수익 확인까지 연결한다.
- 설명을 넘긴 횟수 대신 실제 게임 상태로 학습 결과를 판정한다. 판매나 배송을 가짜로 완료하지 않는다.
- 강제 학습 대화는 시간을 멈춘다. 일반 알림과 선택적 도움말의 정지 정책은 별도로 명시해 운영을 불필요하게 끊지 않는다.
- 기존 저장, 중간 재개, 순서가 다른 성장, 안내 생략, 이미 완료된 조건을 처리한다. 이미 익힌 기능을 다시 강제로 잠그지 않는다.

## 선택과 실제 결과

질문·안심·인사 선택은 답변이나 관계 표현 자체로 의미가 있다. 모든 대화에 금전 보상이나 분기를 붙이지 않는다. 반대로 후원·계약·경쟁 대응 등 사업 선택은 실제 비용·혜택·지연 결과가 있어야 한다.

결과를 예고했다면 해당 거래와 상태 변화를 확인한다. 할 수 없는 벌금·철거·보상이나 알 수 없는 경쟁사 내부 정보를 확정적으로 말하지 않는다. 의미 있는 선택처럼 제시하고 실제로는 동일한 결과만 주는 구성을 피한다. 분기는 재접속과 기한 만료 후에도 처리 가능해야 한다.

## 제출물과 검증

| 상황/단계 | 등장 조건 | 현재 사실 | 대화·응답 | 실제 조작/결과 | 정지 정책 | 재개·생략·복구 |
|---|---|---|---|---|---|---|

대화의 역할을 먼저 확인하고, 인물의 말투를 맞춘 뒤, 불필요한 문장을 줄인다. 모든 응답 경로, 사건 만료·중복 처리·잔액 부족, 한국어/일본어와 작은 화면을 관련 범위에 맞춰 확인한다.

대사가 자연스러워졌다는 판단과 초보자가 혼자 운영할 수 있다는 평가는 구분한다. 튜토리얼 담당은 [게임 설계](game-designer.md)와 [상권·화면 지침](level-designer.md)을 함께 읽으며, [공통 운영 지침](../docs/QUALITY_ROLES.md)에 전체 게임의 학습 공백을 남긴다.
